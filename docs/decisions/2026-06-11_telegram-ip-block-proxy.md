# 2026-06-11 · Обход блокировки IP Telegram через прокси

## Контекст

Прод-бот перестал отвечать. Диагностика на VPS показала: процесс жив и
рестартует по кругу (`NRestarts=42`), в логах
`aiogram.exceptions.TelegramNetworkError: Request timeout error` на старте при
`get_me()`.

Причина — инфраструктурная, не в коде. Провайдер VPS (Москва) **выборочно режет
IP-диапазоны Telegram** на 443:

- общий IPv4-выход работает (Cloudflare/Google отвечают за ~0.1с);
- DNS отдаёт для `api.telegram.org` адрес `149.154.166.110` — **заблокирован**
  (таймаут 15с);
- IPv6 на сервере не сконфигурирован (нет default-route) → мгновенный отказ;
- при этом соседний IP Telegram `149.154.167.220` на 443 **открыт** и отдаёт
  настоящий Bot API.

Бот ходил на заблокированный IP, висел на таймауте и падал → systemd
перезапускал → крашлуп.

## Решения

### Аварийный разблок: пин рабочего IP в `/etc/hosts`

`echo '149.154.167.220 api.telegram.org' >> /etc/hosts` + рестарт сервиса. Бот
поднялся сразу.

- **Почему как временная мера:** один шаг, мгновенный эффект, ноль кода.
- **Цена / почему не постоянное решение:** ручное состояние сервера вне git;
  `/etc/hosts` на этом VPS под управлением Ansible (следующий прогон может
  перетереть); конкретный IP могут закрыть позже. Это заплатка, не контракт.

### Постоянное решение: опциональный прокси к Bot API

Бот умеет ходить к Telegram через прокси — `src/bot/bot_factory.py::build_bot`
прокидывает `TELEGRAM_PROXY_URL` в `AiohttpSession(proxy=...)`. Прокси сам
резолвит `api.telegram.org` со своей (нефильтрующей) стороны, поэтому смена или
блокировка IP Telegram бот больше не ломает. По умолчанию переменная не задана —
сессия прямая, поведение не меняется.

- **Почему на уровне приложения, а не сети (WireGuard):** конфиг лежит в репо и
  раскатывается обычным деплоем, не зависит от Ansible/`/etc/hosts`, трогает
  только трафик бота. WireGuard надёжнее как сетевой слой, но это серверный
  конфиг вне репозитория и требует WG-эндпоинта — избыточно, пока хватает прокси.
- **Почему `aiohttp-socks`:** требуется `AiohttpSession` для `socks4/5`-прокси
  (и http-туннелирования); поддерживаемые схемы — `http` / `socks4` / `socks5`.
- **Цена:** нужна внешняя точка выхода, не фильтрующая Telegram (свой VPS за
  рубежом с SOCKS, VPN-прокси и т.п.) — её предоставляет эксплуатация, не код.
  Без заданного `TELEGRAM_PROXY_URL` фича бездействует.

## Статус

Прод сейчас работает на **пине в `/etc/hosts`** (аварийная мера). Код для
прокси-обхода готов и ждёт внешнего endpoint'а: как только он появится —
прописать `TELEGRAM_PROXY_URL` в прод-`.env`, задеплоить, снять пин из
`/etc/hosts`.
