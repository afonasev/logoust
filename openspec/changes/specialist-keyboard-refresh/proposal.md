## Why

После добавления/переименования кнопок reply-клавиатура специалиста устаревает: Telegram держит её на стороне клиента, пока бот не пришлёт сообщение с новым `reply_markup`. Сейчас единственная точка обновления — успешный `/start <token>`, поэтому специалисту приходится заново вбивать токен из инвайт-ссылки. Это неудобно и провоцирует «потерянные» новые кнопки после деплоя.

## What Changes

- **Автообновление клавиатуры без лишних сообщений.** Исходящий middleware сессии добавляет актуальную клавиатуру к следующему текстовому сообщению без своей разметки, включая фоновые сообщения специалисту. Inline-ответы и редактирования сохраняются; обновление ждёт подходящей отправки или `/start`. Версия записывается только после успешной доставки.
- **Голый `/start` без токена узнаёт известного пользователя (ручной выход).**
  - Специалист по `telegram_chat_id` → текст `[start].already_welcomed` со свежей клавиатурой (и фиксация текущей версии).
  - Клиент по `telegram_chat_id` → вежливое подтверждение «вы уже подключены» вместо нынешнего `[start].no_token`.
  - Никто не найден → прежнее поведение `[start].no_token`.
- Сообщения специалисту по этим сценариям **не** журналируются через client-audit (правило `bot.md`) — только Python-лог.

## Capabilities

### New Capabilities
- `specialist-keyboard-refresh`: автоматическое поддержание актуальности reply-клавиатуры специалиста через версию набора кнопок и piggyback-middleware, без отправки отдельных сообщений.

### Modified Capabilities
- `specialists`: требование «/start без payload» меняется — голый `/start` от привязанного специалиста пере-отправляет приветствие со свежей клавиатурой, а не `no_token`.
- `audit`: событие `connection_confirmed` со статусом доставки клиентского ответа.
- `clients`: голый `/start` от привязанного клиента получает подтверждение «уже подключены» вместо `no_token`.

## Impact

- **БД:** новый столбец `specialists.keyboard_version` (nullable) + миграция → `docs/database.md`.
- **Код:**
  - хелпер `keyboard_version(messages) -> str` (хеш подписей `build_main_keyboard`);
  - middleware исходящих запросов сессии Bot, подкладывающий `reply_markup` при расхождении версии;
  - `src/bot/handlers/start.py` — ветка голого `/start` (узнавание спеца/клиента, bump версии);
  - `src/infrastructure/clients_repo.py` — `find_by_chat_id`;
  - `src/infrastructure/specialists_repo.py` — чтение/запись `keyboard_version`;
  - `src/bot/messages.toml` — клиентский текст «вы уже подключены».
- **Аудит:** новое событие `connection_confirmed` для ответа подключённому клиенту.
- **Доки:** `docs/database.md`, `docs/bot.md`.
- **Не затрагивает:** клиентская сторона по-прежнему без reply-клавиатуры; прокси отложен; подтверждение клиенту включено в client-audit.
