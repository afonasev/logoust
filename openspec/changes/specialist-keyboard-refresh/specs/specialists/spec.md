## MODIFIED Requirements

### Requirement: /start без payload

Бот **SHALL** при получении `/start` без аргументов узнать отправителя по `telegram_chat_id` и ответить в зависимости от роли: привязанному специалисту — текстом `[start].already_welcomed` со свежей постоянной клавиатурой (и зафиксировать текущую версию набора кнопок в `specialists.keyboard_version`); иначе, если отправитель — привязанный клиент, текстом `[start].already_linked`; иначе текстом `[start].no_token`. Ни в одном случае новые записи специалистов не создаются.

#### Scenario: Прямой /start от привязанного специалиста

- **WHEN** привязанный специалист отправляет `/start` без payload
- **THEN** бот отправляет текст из ключа `[start].already_welcomed` с актуальной постоянной клавиатурой специалиста
- **AND** в `specialists.keyboard_version` записывается текущая версия набора кнопок
- **AND** в таблице `specialists` не появляется новых записей

#### Scenario: Прямой /start от привязанного клиента

- **WHEN** пользователь, не являющийся специалистом, но привязанный как клиент по `telegram_chat_id`, отправляет `/start` без payload
- **THEN** бот отправляет текст из ключа `[start].already_linked`
- **AND** в таблице `specialists` не появляется новых записей

#### Scenario: Прямой /start без deep-link от неизвестного пользователя

- **WHEN** пользователь, не привязанный ни как специалист, ни как клиент, открывает `https://t.me/<bot>` и отправляет `/start` без payload
- **THEN** бот отправляет текст из ключа `[start].no_token`
- **AND** в таблице `specialists` не появляется новых записей, существующие записи не меняются
