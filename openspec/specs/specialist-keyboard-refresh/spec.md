# specialist-keyboard-refresh

## Purpose

Обновление постоянного меню специалиста без дополнительных сообщений.

## Requirements

### Requirement: Версия набора кнопок клавиатуры специалиста

Бот **SHALL** вычислять детерминированную версию (хеш) текущего набора подписей кнопок постоянной клавиатуры специалиста (`build_main_keyboard`) и хранить на каждом специалисте последнюю **доставленную** ему версию в столбце `specialists.keyboard_version`.

Версия **MUST** меняться при добавлении, удалении или переименовании любой кнопки и **MUST NOT** меняться при перезапуске бота без изменения набора кнопок. Для специалиста, которому актуальная клавиатура ещё не доставлялась, хранимая версия равна `NULL`.

#### Scenario: Набор кнопок не менялся между релизами

- **WHEN** бот перезапускается без изменения подписей кнопок `build_main_keyboard`
- **THEN** вычисленная версия совпадает с ранее сохранённой у специалистов
- **AND** ни одному специалисту клавиатура повторно не пере-отправляется

#### Scenario: В набор добавили кнопку

- **WHEN** в `build_main_keyboard` добавлена новая кнопка и бот перезапущен
- **THEN** вычисленная текущая версия отличается от версии, сохранённой у специалистов до релиза

### Requirement: Автообновление клавиатуры без отдельного сообщения

Бот **SHALL** при следующем исходящем текстовом сообщении привязанному специалисту без собственного `reply_markup`, если сохранённая версия устарела, добавить актуальную постоянную клавиатуру и сохранить её версию после успешной отправки. Это относится к ответам на действия специалиста и к фоновым сообщениям. Сообщения со своей разметкой и редактирования существующих сообщений **MUST NOT** изменяться ради обновления клавиатуры; обновление откладывается до следующей подходящей отправки. Явная доставка основной клавиатуры через `/start` с payload или без него **MUST** также сохранять доставленную версию.

Бот **MUST NOT** отправлять для обновления клавиатуры отдельное (дополнительное) сообщение и **MUST NOT** фиксировать новую версию, если ответ со свежей клавиатурой не был успешно отправлен.

#### Scenario: Первая подходящая отправка после изменения кнопок

- **WHEN** бот отправляет специалисту с устаревшей `keyboard_version` текстовое сообщение без собственной разметки
- **THEN** ответ бота несёт актуальный `reply_markup` с новым набором кнопок
- **AND** в `specialists.keyboard_version` записывается текущая версия
- **AND** бот не отправляет никакого дополнительного сообщения сверх обычного ответа

#### Scenario: Версия уже актуальна

- **WHEN** привязанный специалист, у которого `keyboard_version` уже равна текущей версии, отправляет боту сообщение
- **THEN** бот не подменяет `reply_markup` ради обновления клавиатуры
- **AND** значение `keyboard_version` не изменяется

#### Scenario: Ответ со свежей клавиатурой не доставлен

- **WHEN** при обновлении клавиатуры отправка ответа специалисту завершается ошибкой доставки
- **THEN** значение `keyboard_version` не изменяется
- **AND** обновление повторяется при следующей подходящей отправке

#### Scenario: Ответ уже содержит inline-кнопки

- **WHEN** обычный ответ специалисту содержит собственную разметку
- **THEN** бот сохраняет исходную разметку и не отправляет дополнительных сообщений
- **AND** версия остаётся устаревшей до следующего подходящего сообщения или явного `/start`

#### Scenario: Успешный онбординг с приглашением

- **WHEN** специалист получает основную клавиатуру через `/start <token>`
- **THEN** доставленная версия сохраняется после успешной отправки
- **AND** при ошибке отправки предыдущая версия не меняется
